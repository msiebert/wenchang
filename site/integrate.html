Choose an integration path#

The memory tools are plain Python methods. There are three ways to put them in front of an agent. All three share the same store, identity resolver, scope policy, and prompt; they differ only in who registers the tools and how a call reaches them.

Path Use it when Entry point
A new MCP server You want a standalone memory server for an MCP client such as Claude Code, over stdio or HTTP. wenchang.mcp.build_server
An existing MCP server You already run an mcp 2.x MCPServer with your own tools, auth, and middleware, and want memory on it. wenchang.mcp.register_memory_tools
Without MCP Your agent uses another tool framework, or calls a model API directly with its own tool loop. wenchang.tools.bind_tools

The MCP paths need the mcp extra and work only with mcp 2.x MCPServer. The path without MCP needs only the base package.

Whichever path you take:

  • Concepts explains paths, scopes, files, versions, and limits.
  • Identity and multi-tenant auth explains how a caller becomes a set of scopes.
  • Customizing the prompts explains the prompt the agent needs alongside the tools.
  • Storage and operations covers the bucket, costs, caching, and erasure.
